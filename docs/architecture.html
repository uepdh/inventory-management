System Architecture

Three tiers in one repo. The browser loads the SPA from Vite, and the SPA calls the API by absolute URL. There is no Vite proxy, so cross-origin access depends on the backend's wildcard CORS.

Data Flow

Two paths matter: the read path triggered by the global filters, and the single write path on the Restocking page.

Read path: changing a filter
1FilterBar

User picks a period, warehouse, category or status. Bound to refs in useFilters.

2View watcher

The active view watches the shared refs and calls getCurrentFilters() which maps them to {warehouse, category, status, month}.

3api.js

Drops any value equal to 'all', then issues GET /api/orders?… or GET /api/dashboard/summary?… via axios.

4FastAPI route

Reads query params, runs apply_filters and filter_by_month over the module-level lists. Nothing is mutated.

5Pydantic

List endpoints validate against Order or InventoryItem. Aggregated endpoints return plain dicts.

6Refs and computeds

Raw rows land in a ref such as allOrders. Computed properties derive KPIs, tables and SVG chart series. Currency conversion to JPY is display-only.

Write path: placing a restocking order
1Budget slider

Restocking view calls GET /api/restocking/recommendations?budget=N on each change.

2Greedy recommender

Forecasts with demand gaps are sorted by gap size then trend priority, and the budget is allocated item by item.

3POST /api/restocking/orders

Validates items and quantities, prices lines from forecasts, sets lead time to the max line, returns 201.

4In-memory append

The order is pushed onto restocking_orders and shows on the Orders page. It disappears when the server restarts.

Testing

pytest with FastAPI's TestClient. The client fixture imports app straight from server/main.py, so tests run against the real in-memory data with no mocking. Four files cover inventory, dashboard, restocking, and the demand, backlog, spending and root endpoints. There are no frontend tests and no tests for the orders or reports endpoints.

cd tests && uv run pytest -v

Running locally

Backend: cd server && uv run python main.py. Frontend: cd client && npm install && npm run dev. Swagger UI at localhost:8001/docs, app at localhost:3000. The shell scripts in scripts/ wrap the same commands for macOS and Linux.

Things Worth Knowing

Observations from reading the code that are not obvious from the README. Useful before changing anything.

BugSix api.js functions hit routes that do not existThe task and purchase-order helpers call /api/tasks and /api/purchase-orders, which main.py never defines. App.vue calls getTasks() on every mount and swallows the 404, so the Tasks modal only ever shows the four mock tasks.
BugDashboard references an unregistered component<PurchaseOrderModal> is rendered in Dashboard.vue but no such file exists and nothing imports it. Vue warns and renders nothing. Looks like a half-reverted feature, matching the empty purchase_orders.json.
GapReports bypasses the API clientReports.vue hardcodes http://localhost:8001 twice and calls axios directly. It is also the only Options API view and the only one still carrying debug logging.
GapGlobal filters are inert on two pagesFilterBar renders on every route, but Restocking and Reports never import useFilters, so changing a filter there has no effect.
GapNo Vite proxy, absolute backend URLThe app only works when served from localhost and relies on wildcard CORS. Wildcard origins combined with allow_credentials=True is also an invalid pairing.
GapDashboard backlog count ignores filterstotal_backlog_items in the summary is always the full count of four, regardless of warehouse or category.
NoteSeed script is out of sync with shipped datagenerate_data.py uses a Widgets / Components catalog, but the live data uses Circuit Boards, Sensors, Actuators, Controllers and Power Supplies. Re-running it would break the FilterBar's hardcoded categories.
NoteTest docs are staletests/README.md describes a test_orders.py that does not exist and omits test_restocking.py. Orders and reports endpoints have no coverage.
NoteTool-usage hook is not wired up.claude/hooks/post-tool-use.sh exists, but no settings file registers it, so it never runs.
